# Schedules and computer use

For user-requested scheduled work, author mode can call `apr_manage` with `schedule.create`: use a registered immutable process reference, input/config overrides, stable request key and a once, interval or UTC cron trigger. Explicitly convert the user's timezone to the required timing; do not assume cron is local time. Inspect via `apr_inspect` views `schedules`/`schedule`, and pause/resume/delete through `apr_manage`. Jobs persist after client disconnect or attachment expiry. They require an awake host and running service; a saved caller request does not automatically wake this conversation. Pause/delete prevent future occurrences while existing runs keep their own controls. Changed process/config/binding definitions require a new schedule/key.

For a scaffolded computer-use process, a `computer_decision` request asks for a supplied action choice, not for you to execute that action. The native worker performs its own freshness/app checks. `computer_review` requires observed completion evidence or a stopped result. Jev saying done is insufficient. An explicit frozen visible-text success condition may finish independently; otherwise review remains pending. Do not bypass missing OS grants, app scope, stale observations or unresolved effects. The macOS helper shares the physical desktop and uses a nonblocking exclusive lock per observation/action; desktop_busy stops rather than queues an old click. It does not inherit client tools.

For interactive website work by the agent, use the Codex in-app browser (`iab`) through `cua_repl`. When the owner explicitly requests a reusable APR browser recipe, use installed `apr computer browser-scaffold`: select the explicitly prepared Playwright Chromium executable, start URL and exact `--origin` destinations. Derive `--recorded-plan` (click/label/expected_text JSON) from a successful reference run and provide `--success-text`. Successful recorded reuse uses zero model calls; each action retains its own effect intent and fresh state/postcondition checks. Without a recorded plan, caller or Jev can choose observed clicks/scrolling. Fresh headless sessions use no user profile/logins or physical desktop. Source, executable SHA, origins and plan are frozen; the runtime-issued run ID and goal bind the private time-limited session. Install requirements-browser.txt and Chromium once in a private Python environment, then request the normal owner Python grant. Scaffolding never installs, grants or executes. This initial browser helper does not expose free text, password entry, arbitrary scripts, uploads/downloads or persistent logins. Expired/uncertain sessions are not silently recreated or replayed.

Worker diagnostics retain fixed categories and exit codes only. Native exits 71/72/73/74 locate observe/validation/dispatch/post-action-verification failure, and 76 indicates browser failure. These locate a stage, not proof that no effect occurred; inspect scoped effect.unfinished events and reconcile before retrying. Never ask the user to paste raw secrets or child stderr.
