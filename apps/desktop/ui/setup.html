SETTINGS & ACCESS

Connect your agent

Connect once. Your agent creates projects and recipes as you work.

Connect once, use in any project

Choose your agent and connect CookBook. Then open any project in your agent and describe what you want to do. Your agent creates the CookBook project and recipes for you.

Optional: let Codex call CookBook recipes without its usual per-call approval. This applies to projects using this user-level connection; project-only connections may take precedence. CookBook still checks workspace permissions and execution grants; native recipes retain their approved computer access. Other agent actions keep their existing approval rules.

Your tools & accounts
Connect an account once, then approve the operations each recipe needs. Sharing a tool with all projects is optional. Credentials stay in a private local TOML file outside your projects. Recipes reuse them without Keychain prompts.
Each saved tool keeps its exact destination and permissions. Adding different operations still requires your review.
Credential storage
CookBook saves keys automatically. The file is readable only by your macOS/Linux user, but it is not encrypted: other programs running as you can read it. It is excluded from CookBook backups. Do not commit or share it.
For an earlier CookBook installation, import saved keys once. Your operating system may ask for permission to read the old entries. CookBook will keep those entries for rollback and use the local file for future calls.
Saved accounts
Disconnecting an account stops future calls through every tool using it. Disabling one tool leaves the account available for other approvals.

Access requests
Your agent proposes a connection and analyzes the recipe’s payloads. Review the destination, tool, input constraints, cost assumptions, and which projects may use it. Keys are stored once; recipes use approved tools without receiving the key.


Connect a service
Your agent can prepare a connection for you in Access requests. To add a remote MCP service yourself, enter its address, then sign in or paste an API key. CookBook saves the account for future recipes.
Advanced service settings
Your agent can prepare these from the service’s documentation. Most users can leave them unchanged.
Connecting reads the service’s tool list. Recipes still need your approval before using a tool.


OAuth browser sign-in
For a connection your agent has proposed, discover the authorization contract here, then attach it to the public proposal. Leave the client ID blank to use the provider’s advertised registration method. Registration happens only after you approve browser sign-in. Your browser handles login; CookBook never requests your password.


MCP requests needing attention
These requests come from an external server. Never enter passwords, API keys, or payment details in a form. Sampling requests require an actual model result from your agent; this window does not fabricate one.


Execution

Billing period & budget
Totals cover all calls in the selected half-open time window, not just one page. Estimates, provider reports, and imported invoice amounts describe overlapping evidence and must not be added together.
Configure a dispatch budget
Amounts below use integer nanocurrency units: 1 USD = 1,000,000,000. Each attempt reserves the reviewed maximum. This blocks further APR dispatch at the limit; it cannot control charges incurred outside APR or a provider that exceeds its reviewed maximum.
Import and reconcile billing evidence
Your agent can normalize a provider's invoice/API export into this format. Imports require exact connection, time, currency, and attempt matches; unmatched costs are not assigned to a recipe by guesswork.


Automatic price checks
Your agent can select a public JSON source that maps each configured meter name to its rate object. CookBook checks at the approved interval and creates a review request when rates change. Historical pricing and permissions never change silently.


Desktop updates & maintenance
Updates require the publisher's pinned signing key. Development builds without a publisher configuration cannot install updates. Active recipes must finish before replacement; CookBook takes a backup first.


Advanced connection proposal
Normally your agent creates this during recipe authoring. Public configuration only: never paste a credential here.


Allow Python recipes
Some recipes use Python to process files or data. Approve its environment once for a workspace; recipes reuse that approval. A changed interpreter requires a new review.
Your agent can prepare this environment and give you its path. Existing packages stay in that environment; CookBook does not install dependencies here.


Runtime controls
Closing CookBook does not cancel accepted runs. The device must remain awake. Stopping the service prevents execution until it is started again.


Credentials stay in your private local TOML file. You choose which tools are available to all projects and which stay in one workspace. No owner commands are exposed to recipe tools or artifact previews.
