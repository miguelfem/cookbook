## Required crash points

| Point of interruption | Expected recovery |
|---|---|
| Start committed, response lost | Same start key returns the original run |
| Pure attempt leased, output uncommitted | Expired lease can produce a bounded new attempt; stale completion cannot overwrite it |
| Object published, result transaction absent | No phantom successful step; unreferenced object is later collectible |
| Result committed, next scheduling not done | Downstream eligibility is reconstructed; completed work is reused |
| Handoff saved, client never received it | Authorized inspection/claim returns the pending request |
| Result receipt committed, acknowledgement lost | Same semantic submission returns the receipt even if its original token is consumed |
| External effect accepted, response lost | Saved uncertainty/reference enters reconciliation; no blind write retry |
| Decision committed, branch not scheduled | Reuse the decision and schedule the recorded selected path |
| Child created, parent reply lost | Parent locates its existing child dispatch identity |
| One child complete, sibling waiting/failed | Reuse completed outputs, preserve pending/failure state, and do not prematurely join |
| Cancel/revocation races with dispatch | No new effect after the enforced dispatch boundary; already in-flight work remains accounted for |
| Migration interrupted | Reopen a valid supported state or restore the verified snapshot; avoid partially accepted schema upgrades |

Use repeated concurrent stress only for a demonstrated race or release reliability gate; deterministic targeted crash scenarios are the ordinary development loop. Record seeds when randomized scheduling or property tests are used.
