# Execution-boundary review fixtures

These synthetic 0.2 manifests and review sidecars document two authoring choices. They use invented record, policy and update services. No connection or credential is included. The sidecar counts are design estimates with unknown token fields, not observed model calls or savings.

- `service-process.json` has two `mcp.call` reads and zero agent steps. The caller may already have equivalent service tools, but CookBook still needs its own owner-approved bindings. `service-review.json` records those bindings as pending; readiness should block until setup rather than substitute a routine caller handoff.
- `mixed-process.json` prepares facts through the same service steps, asks the caller for one bounded judgment, then writes with the prepared expected revision. `mixed-review.json` records the reason for that boundary. A pending judgment prevents the write; actual conflict and lost-response behavior must be checked with a disposable runtime and approved fixture connections.
- `context-process.json` freezes `context-helper.py` as a trusted Python worker. It generates and aggregates a 1,200-row synthetic dataset in 75-row pages, preserves the complete JSONL as an artifact, and returns a brief under 2 KiB with a stable revision. An unchanged revision returns only `status` and `revision`; changes identify added, changed and removed guidance IDs. A missing required page returns the explicit business failure `status: incomplete` with the missing index and no raw artifact; the protocol run itself completes so the exception remains inspectable. `context-review.json` records the output budget. The owner must approve the pinned Python interpreter before this helper can run; native scripts are trusted host code.

The core admission and audit tests check manifest validity and boundary metadata. The runtime `authoring_boundaries` tests adapt the service manifests to a checked-in local MCP server: pending access blocks, approved service work uses zero handoffs, a mixed run waits for judgment, and start/resume replay does not repeat its write. The same target executes the frozen helper against disposable state and reads back all 1,200 artifact rows while checking actual result bytes, unchanged context, removed guidance and explicit missing-page output. These fixture results do not prove live service quality, uncertain-effect reconciliation or measured token savings.
